# 隐私说明

> 适用于当前 Linux 桌面版。本文描述应用在本机的存储和联网边界；历史网络探针记录有明确日期，不能替代新功能的验证。

## 一句话

NekoWite 不收集遥测、不需要账号。本地知识库的编辑、保存、搜索、图谱、导出、历史与回收站无需联网；AI 请求、智能体、Git 同步和 SSH 远程工作区可能连接外部服务，具体取决于你的操作和配置。

## 什么会离开这台电脑

- 本地知识库的启动、编辑、保存、建立索引、图谱、导出 PDF/HTML 只读写本机文件；若知识库位于 SSHFS 挂载目录，读写会经 SSH 传到远端。
- 以下四类应用内 **AI 动作**会请求你配置的 AI 服务：

| 动作 | 触发方式 | 发送的内容 |
| --- | --- | --- |
| 续写 | 编辑器里按 `Tab` | 光标前最近 200 个字符 + 一句续写指令 |
| 聊天 | 信息栏「AI」页签 | 你输入的消息；开启「引用当前文档」时另附当前笔记/选区上下文；附加的图片以 base64 一并发送 |
| 选区改写 | 选中文字 → 工具栏 ✨（AI 改写 / 润色 / 翻译） | 选中的那段文字 + 对应指令 |
| 插件 AI | 知识库插件调用宿主 AI（发行版不加载知识库插件，因此这条在当前发行版中不会发生） | 插件自己构造的提示词 |

- 「笔记上下文长度」就是聊天附带正文的上限；超长笔记保留开头与结尾，中间省略的部分会在上下文里注明。
- 发往哪里由你决定：设置 → AI 的「服务商」与「接口地址（Base URL）」。默认指向本机（`http://localhost:1234/v1`，本地模型服务）；只有你选择云端服务商时请求才会离开本机，并适用**该服务商自己的隐私条款与数据政策**。NekoWite 不代理、不转发，也不会再发给任何第三方。
- 请求体里只有：模型名、提示词（含上表文本）、可选系统提示词、温度、最大输出 Tokens、思考深度，以及你附加的图片。没有设备标识、没有文件清单、没有使用统计。
- 服务商当然能看到请求的来源 IP 与时间——这是任何联网行为都有的信息；除此之外 NekoWite 不添加任何额外字段。
- 关掉设置 → AI 的「启用 AI 功能」后，应用内 AI 请求不会发出；这个开关不控制独立 ACP 智能体、Git、SSH、形象库或智能体目录。

## 本机存了什么、存在哪里

### 知识库文件夹（vault，你自己选的那个目录）

- 笔记本身：`.md` / `.mdx` 文件，位置与内容完全由你掌控。
- `<笔记名>_assets/`：粘贴或拖入编辑器的图片，保存在该笔记旁边；笔记还没保存时先暂存在 `.tmp/`，保存后移入。
- `attachments/`：应用为你插入的图片（例如 AI 生成的 SVG），按 `YYYY-MM` 分月。
- `daily/`：每日笔记。
- `templates/`：你自己的模板（可选）。
- `plugins/`：vault 插件（`plugins/<插件名>/package.json` 与它指向的入口文件）；只在你放置后才存在。
- `.nekowite/`（应用维护的目录）：
  - `index/manifest.json`、`index/shard-*.json`：全文搜索索引。为了内容搜索，索引保存每篇笔记的**小写全文文本**——只在本机，仅用于加速搜索；删掉它只会让下次搜索重新建索引。写入过程中同目录会出现 `<文件名>.json.tmp`。
  - `history/<转义后的笔记路径>/<毫秒时间戳>.<扩展名>`：每次保存前的旧版本快照（每个文件默认保留最近 10 个，可在设置 → 编辑器 →「历史版本上限」修改）。笔记路径整体是**一个**目录名：`/`、`_`、`%` 与开头的 `.` 会被转义（`docs/a.md` → `docs%2Fa.md`），所以历史目录不会跟着笔记的文件夹层层嵌套。
  - `plugin-governance.json`、`plugin-governance.mackey`：插件的信任、撤销与版本策略（带 HMAC 校验，被篡改时其中的信任会被拒绝）。
  - `vault-plugin-audit.log`：插件治理审计日志。
- `.nekowite-trash/`：回收站。删除的笔记移到这里，可以恢复；只有「清空回收站」才会真正删除。

写入过程中，被写入文件所在的目录里会出现 `.nekowite-<数字>.tmp` 临时文件；写入完成后立刻改名到目标文件。崩溃留下的残片会在该目录下次保存时清理，且只清理名字符合这个形状的文件——你自己的 `draft.tmp` 不会被删。

### 系统目录

应用的数据目录叫 `dev.nekowite.app`：Windows 是 `%APPDATA%\dev.nekowite.app\`，Linux 是
`~/.local/share/dev.nekowite.app/`（下面写作 `<数据目录>`）。

- `<数据目录>/.nekowite/`
  - `stronghold.bin`：**API Key 的存放处**，Stronghold 加密快照，不是明文。
  - `master.key`：打开该快照所需的密钥文件。没有设置主密码时，它保存的是系统生成的随机密钥，边界是本机账户的文件权限；设置了主密码（设置 → AI → 主密码）之后，改为 Argon2id 派生的密钥，文件里只留下盐与一次性校验值。
  - 界面永远拿不到真实 Key：`load_ai_key` 只返回掩码 `••••••••` 表示「已配置」，真实取用只发生在 Rust 内部发请求时。
- `<数据目录>/` 下的其余目录：
  - `agent-runtime/`、`downloads/`、`agent-recovery/`：内置智能体引擎的各版本、正在下载或已验证的候选、以及回滚保留的旧版本。
  - `agent-profiles/`：每个智能体的配置档案（含它自己的服务商与模型设置）。
  - `agent-catalogue/`、`desktop-pet/`：智能体注册表与桌面宠物形象库的本地缓存。
  - `localstorage/`、`storage/`、`CacheStorage/`、`WebKitCache/`、`hsts-storage.sqlite` 等：WebView 自己的用户数据目录（Linux 上是 WebKitGTK，Windows 上是 WebView2）。界面设置就存在这里：
    - 主题/配色/字体、编辑器偏好、默认视图、自动保存间隔、历史版本上限、导出默认值。
    - 最近打开的知识库路径、上次打开的标签页、收藏与最近列表（按知识库分别保存）。
    - AI 配置：服务商、模型、Base URL、温度、上下文长度、系统提示词、思考深度、写入权限、总开关（**不含 Key**）。
    - `nekowite.ai.audit`：本地 AI 活动记录（见下）。
    - `nekowite.chat.sessions`：聊天会话记录（聊天文本与附加图片；超出存储上限时会截断或丢弃较早的图片）。
- 导出：PDF / HTML 写到你自己选择的路径（PDF 通过系统打印对话框完成）。

## AI 权限模型（白话版）

- **应用内 AI 总开关**：「启用 AI 功能」。关闭后不发出应用内 AI 请求，相关 AI 写入一律拒绝；权限设置会保留，重新打开即恢复原样。外部 ACP 智能体有自己的联网行为和授权边界。
- **AI 修改文档的权限**，三档：
  - **每次询问（推荐，默认）**：AI 想写入时弹窗说明要做什么，可选「允许这一次」或「本次运行内始终允许」。授权按**操作种类**生效——允许「插入到光标处」不会顺带允许「替换选中的内容」或「替换整篇文档」。
  - **直接写入，不再询问**：不弹窗，直接写入。
  - **禁止 AI 写入文档**：永不写入；需要写入的 AI 动作连请求都不会发出。
- **本地 AI 活动记录**：设置 → AI →「最近的 AI 活动」。每次 AI 写入与每次拒绝记一行：时间、来源（续写 / 聊天 / 选区改写 / 权限弹窗 / 插件）、写入种类、结果与一行说明。**不记录任何正文内容**；最多保留 200 条，面板上有「清空记录」。

## 不收集什么

- 没有遥测、使用统计或崩溃上报。设置 → 关于中的“检查更新”仅在你点击时请求 GitHub Releases API（`api.github.com/repos/NekoRain404/NekoWrite/releases/latest`），只发送标准 HTTPS 请求元数据，不发送笔记、路径、配置或设备标识；应用不会自动下载或安装更新。
- **以下操作可能联网**：
  - **你自己配置的 AI 请求**（见上一节）：包括「刷新模型列表」，它也走你的服务商。
  - **桌面宠物的形象库**：打开设置 → 桌面宠物 → 形象库时，会去 `pets.thenightwatcher.online` 取清单（`desktop_pet/resources.rs` 的 `LIBRARY_ENDPOINT`）。它不经过 AI 设置，也不带任何凭据。
  - **智能体注册表**：打开智能体目录时，会去 `cdn.agentclientprotocol.com` 取注册表（`commands/agent_catalogue.rs` 的 `REGISTRY_URL`），同样不带凭据。
  - **Git 同步**：你配置远端并点击拉取或推送时，本机 Git 连接该远端。提交只在本地进行；认证遵循本机 Git / SSH 配置，应用不保存 Git 密码。
  - **SSH 远程工作区**：实时挂载通过 `sshfs` 访问服务器，打开和保存挂载目录下的文件会读写远端；复制导入通过 `rsync` 下载副本。输入的密码只用于本次连接，不作为连接配置持久保存。
  - **ACP 智能体**：完全版附带的 `opencode` 或你自行注册的程序是独立进程，可能直连自己的服务商，不经过 NekoWite 的请求层，也不受应用内 AI 总开关控制。
  - **历史验证范围**：2026-09-22 的代理探针验证过当时的启动、空闲、形象库、注册表与远程图片渲染行为；它没有覆盖后续增加的 Git、SSH 或 ACP 外部程序。复现：`node apps/desktop/e2e/webkit/probe-egress.mjs`（需 `xvfb-run` 与已构建的应用）。
- 文档里的**远程图片不会被加载**（受安全策略限制，界面显示「远程图片未加载」），因此渲染笔记不会顺带发起网络请求。
- 应用写入知识库和上述数据目录；选择 SSHFS 实时挂载时，知识库中的远程目录对应服务器文件，Git 提交会在知识库中创建或修改 `.git/`。

## 怎么自己核对

- 设置 → AI：核对服务商、Base URL、模型，以及「最近的 AI 活动」里记录了什么。
- 用文件管理器打开你的知识库：`.nekowite/`、`.nekowite-trash/`、`attachments/`、`daily/` 都在其中（需要显示隐藏文件）。
- 打开数据目录下的 `.nekowite/`（Windows：`%APPDATA%\dev.nekowite.app\.nekowite\`，Linux：`~/.local/share/dev.nekowite.app/.nekowite/`）：`stronghold.bin` 是加密的二进制文件，用文本编辑器看不到明文 Key。
- 断网测试：本地知识库的编辑、搜索、图谱、导出、历史和回收站仍可用；Git 拉取/推送、SSH 挂载以及云端 AI 会失败，挂载目录的文件也可能不可读写。
- 想禁止出站：不要连接 Git / SSH 远端或启动联网的 ACP 智能体；关闭「启用 AI 功能」只能阻止应用内 AI 请求。系统防火墙需同时覆盖应用及其启动的 `git`、`sshfs`、`rsync` 和智能体进程。
